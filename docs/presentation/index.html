    Two reading-list exporters

    One worker writes a Markdown table and another writes a plain-text list. Your main agent connects both to the CLI and tests them together.

    1. Agree on the fields

      You $adaptive-task Add Markdown and plain-text exports to the reading-list CLI. Preserve each title, author and position in the list.

      Primary Both renderers can use the existing ordered list of title and author pairs. I’ll keep the CLI wiring here and give each renderer its own module and tests.

      Shared input. Both assignments can start as soon as the record format is settled.

    2. Give each writer its own files

      You Can the two formats be implemented together?

      Primary Yes. One Luna assignment covers the Markdown table and its tests. A second covers the plain-text list and its tests. Each can run against the same fixture without editing the other’s files.

      Ownership. Separate files let both workers start while the primary handles the CLI.

    3. Check both formats through the CLI

      Worker returns Both renderers are ready for review.

      Primary I’ll inspect both changes, connect the format switch, then run each export through the CLI. Using two books with the same title and different authors checks that both records survive in order.

      Dependency. Trying both formats through the same command catches mistakes that renderer tests can miss.

    4. See who did what

      You Who did what, and what did you check?

      Primary The workers wrote the renderers. I connected them to the CLI and checked titles, authors and order in both outputs. The run confirms Luna Max wrote the Markdown renderer. The model for plain text is still unknown.

      Evidence. The returned files show what each worker contributed. Codex checks the run records before naming the model or reporting tokens.

    One Luna investigation

    Luna investigates a parser defect. The primary reviews the evidence and decides what to do next.

    1. Choose Luna for an investigation

      You $luna-task Investigate why the CSV importer drops quoted newlines. Return a reproduction and proposed fix. Keep this pass read-only.

      Primary I’ll give Luna the importer context and ask for a small input that reproduces the failure.

      Invocation. An explicit Luna task selects Luna as the only delegated model.

    2. Keep the investigation read-only

      You Preserve the other work in the checkout.

      Primary Luna will read the parser and its tests, then bring back a failing input and a proposed change.

      Ownership. The primary identifies the files, the requested outcome and a way to check it.

    3. Check the reproduction

      Worker return The importer splits a quoted field at a newline. Here is the two-row input that triggers it.

      Primary I’ll run the input through the importer and check that the proposed parser change addresses the cause.

      Evidence. The primary inspects the return. Native execution records establish which model ran.

    4. Return the finding

      You What would you change?

      Primary The importer splits physical lines before parsing CSV quoting. I’d pass the input stream to the CSV reader and use the two-row fixture for a regression test. This investigation ends with the proposal.

      Next step. For a substantial goal involving several Luna assignments, explicitly request $luna-goal-loop.

    Two independent sessions

    Another agent owns the packaging report. Ask it to tell you when the draft is ready, then send it a follow-up from your own session.

    1. Identify the session

      You Watch the session preparing the packaging report and tell me when it is ready.

      Primary I’ll look at the project and recent work. If two sessions match, I’ll ask you to choose.

      Selection. Codex can find independent sessions open on the same daemon. Workers report back through the agent that assigned them.

    2. Follow the selected peer

      You Follow that report session.

      Primary I found the session preparing the report. I’ll watch for readiness or a request for input while you keep working.

      Observation. The watch stays bound to the selected peer. Passive reads leave its work intact.

    3. Find out what’s ready

      Peer update The report owner marked the draft ready.

      Primary The draft is available for review. Its owner says the risk summary is still pending.

      Handling. A peer can report a draft ready while parts of the handoff remain open.

    4. Send a request and stop the watch

      You Tell that session to include the risks, then stop watching it.

      Primary The report agent agreed to add the risks. I’ve stopped watching. We’re still waiting for word that the edit is ready.

      Receipts. You can check whether the other agent accepted the request. The report session keeps working after you stop the watch.

    An export that stops making progress

    A background command follows a running job. Codex checks in when the job stops making progress.

    1. Say what counts as a stall

      You Watch this run and tell me if it stalls or fails.

      Primary I’ll check where the run reports progress and how long it normally goes between updates. Which run should I follow?

      Scope. The watch uses the access already configured for the session.

    2. Register a quiet watch

      You The export run. Flag it if the completed count stays flat for ten minutes.

      Primary I’ve registered the watch. I’ll report a stall, failure or loss of access. Routine reads can stay quiet.

      Observation. Short commands or a continuing script can poll without a model turn per read.

    3. Spot the stalled export

      Endpoint update Running. 42 of 80 files exported.

      Primary The export still says “running,” but the count has been at 42 for ten minutes. It looks stalled.

      Follow-up. You get the file count here and can decide what to do about the stalled export.

    4. End observation

      You Stop watching that run.

      Primary I’ve stopped watching the export. The job is still running.

      Control. Explicit cancellation closes this observation and prevents renewal or replacement.

    A later check and browser report

    You have other work to do while a deployment settles. Ask for one later check and a report at your usual address.

    1. Ask for one later check

      You Check the deployment in twenty minutes. Put its status and any remaining risks in an HTML report.

      Primary I’ll set a reminder to check the deployment tool once and use what it reports.

      Scheduling. Registering the check leaves the conversation available for other work.

    2. Return to the conversation

      You Work on something else in the meantime.

      Primary The later check is registered. It can wait behind an active turn until the conversation is available.

      Ordering. A reminder is a one-shot request. Inspecting the MCP source takes a native model turn.

    3. Read the configured source

      Reminder Time to check the deployment.

      Primary The deployment tool now reports ready. I’ll include its result, the time of inspection and the remaining risks in the report.

      Permissions. The inspection uses the configured connection and its normal approvals.

    4. Open the deployment report

      You Give me the report link.

      Primary The deployment report is ready. It shows the status I found, when I checked, and the risks still open. I verified that the report host is serving the saved copy.

      Delivery. You can reopen that snapshot after the session ends from a browser that can reach the report host.

    A return to unfinished work

    Come back to a busy thread and find out which updates you’re still waiting for.

    1. Pick up the same conversation

      You What am I still waiting on?

      Primary I’ll look up what we’re watching, which checks have come back, and whether the packaging agent replied.

      Inspection. Catching up reads the saved history. You can ask separately for a fresh check.

    2. Read the stored receipts

      You Show me the outstanding follow-ups.

      Primary We’re still watching packaging. The CI check came due, but I don’t have its result yet. The packaging agent agreed to review the release notes. We’re waiting for its reply.

      Coverage. This recap uses cached receipts for this conversation. Fresh source status would require another check.

    3. Identify a failed follow-up

      Stored receipt The CI follow-up turn failed.

      Primary That check still needs attention. Its stored receipt records the failure. No successful result or retry is recorded.

      Outcome. A failed or interrupted follow-up stays visible until the reminder is explicitly cancelled.

    4. Close the selected reminder

      You Cancel the failed CI reminder.

      Primary I’ve cancelled that reminder. You can still see the failed check in its history. I’m still watching packaging.

      Control. An acknowledged follow-up with no terminal receipt has an unknown outcome.

    Pausing, stopping and catching up

    What does Esc do?

    Esc interrupts the foreground turn. Your watches and reminders keep going until they expire or you cancel them. Say “Stop watching that run” to end one watch.

    Does stopping a watch stop the job?

    The job keeps running. Codex stops checking it. An update already queued in your conversation can still arrive.

    What happens when a watch expires?

    The observation ends when its time or event allowance runs out. The primary can explicitly continue useful observation under the existing request. The job’s own status determines whether it finished.

    Can I leave the terminal?

    You can detach the TUI and leave watches running while the owning daemon is available. After a verified daemon restart, eligible watches can resume within their original limits. History shows any gaps.

    Which sessions can I reach?

    Peers are independent loaded sessions in the same daemon. The primary uses separate native worker controls to assign and review its child agents. Each daemon has its own peer directory.

    Which permissions does a watch use?

    Watches use the source access already configured for your session. Changing a job or taking another action requires authorization for that action.

    How do I pick up unfinished work?

    Ask “What am I still waiting on?” Codex reads this thread’s saved follow-ups and tells you how recent they are. Ask for a fresh check if you need to know what’s happening now.

    What does a receipt confirm?

    A delivery receipt tells you the message arrived. Acceptance means the other agent agreed to the request. Look for its reply or the finished work to see how it turned out.
